# 项目上下文

## 项目

- 名称：剪映视频助手
- 仓库：`jianying-video-assistant`
- 状态：首版开发阶段；素材文件夹导入与分类已形成真实可用闭环

## 产品目标

把“找素材、找文案、配音乐、生成剪映草稿”合并为一条轻量的成片准备流程，减少重复导入、跨页面选择和手工整理。

## 首版范围

1. 素材分类：文件夹导入、自动建议、快速纠错。
2. 内容文库：按用途检索片段，一键送入项目脚本。
3. 背景音乐：按情绪和时长推荐、试听、应用。
4. 剪映草稿：汇总当前项目，一次检查后生成草稿副本。

## 核心原则

- 以“当前视频项目”为中心，不要求用户先维护四套独立资料库。
- 每个功能都允许拖入即用，分类和元数据是渐进补充而非前置门槛。
- 常用动作最多两步完成；高级设置延后展示。
- 所有自动识别都可撤销、可人工覆盖。
- 永不静默修改用户的原始媒体和现有剪映草稿。

## 当前技术决策

- C# + WinUI 3 + Windows App SDK。
- 单项目解决方案，MVVM 分层。
- 使用系统 Backdrop：Windows 11 优先 Mica；不支持时回退为半透明主题背景。
- 初版使用内存演示数据，后续本地持久化采用 SQLite。

## 开发与验证环境

- 主源码工作区：macOS 上的本 Git 仓库。
- Windows 构建机：`gryps@192.168.31.36`，远程镜像目录为 `C:\Users\gryps\source\jianying-video-assistant`。
- 构建机使用当前用户目录中的 .NET SDK `10.0.401`；未修改系统级 PATH。
- 2026-09-13 已完成 Windows x64 Debug 构建：0 个警告、0 个错误；可执行程序 5 秒启动冒烟测试通过。
- 2026-09-13 素材导入版本通过 Windows x64 解决方案构建（0 警告、0 错误）和核心流程冒烟测试。
- 构建机尚未安装剪映，因此草稿格式和交互式桌面视觉仍未验证。
- 当前开发构建依赖 .NET 10 Desktop Runtime；`win-x64-self-contained` 发布产物已配置为携带 .NET 10 和 Windows App SDK，目标机无需另装运行时。
- 素材版本启动验证期间，构建机在 `Microsoft.UI.Input.dll` 触发 `0xC0000602`；独立重建初始提交也复现相同故障，说明它不是本次功能代码的特有回归。需恢复该机 WinUI 图形运行环境后再做交互验收。

## 已实现的素材闭环

- 系统文件夹选择器、递归扫描图片/视频、完整路径去重。
- 基于文件名和目录名的五类规则建议，可在列表下拉框中纠正。
- 无权限目录统计、导入状态、文件类型/大小/相对路径展示。
- 扫描只读取素材，不移动、不重命名、不修改源文件。

## 当前首页约定

- 首页以“添加素材、添加视频文案、选择背景音乐、导出剪映草稿”四步呈现。
- 只有真实可用的素材入口可以操作；其余步骤在实现前标注“后续版本”并禁用。
- 不使用只改变演示状态的假按钮；每个入口必须能说明打开的界面和最终产出。
