# 剪映视频助手：产品基线

## 1. 权威来源

本客户端是 `192.168.31.24:8000/workbench/` 中“视频生产”模块的 Windows 桌面入口，不是另一套独立产品。

- 运行中的 Web 工作台、服务端 API 和数据库是业务事实来源。
- Windows 客户端共享同一账号、产品、标签、素材、文案、音色、旁白、音乐、模型配置和草稿记录。
- Web 产品规则变化时先修改权威 Web 项目，再由客户端直接获得更新；不得在客户端复制一套不同的业务流程。
- WPF 只负责可靠启动、承载工作台、Windows 文件选择、下载和外部链接衔接。

此前“当前视频项目 + 四张任务卡”的设计与权威 Web 产品不一致，自 2026-09-15 起废止。

## 2. 信息架构

```text
视频生产
├── 生产总览
├── 素材归类
│   ├── 产品名称管理
│   └── 标签分类 / 标签名称管理
├── 内容文库
│   ├── 文案
│   ├── 音色库
│   └── 旁白与字幕
├── 背景音乐
├── 剪映草稿
└── 模型配置
```

生产总览展示已归类原视频、可用文案、可用背景音乐和剪映草稿四项指标，以及“素材归类 → 内容文库 → 背景音乐 → 剪映草稿 → 剪映内精修”的五步生产路径。不存在必须提前命名的“当前项目”。

## 3. 业务规则

### 3.1 素材归类

1. 用户先维护或选择一个产品。
2. 标签由“标签分类 + 标签名称”组成，并在所有产品间共享。
3. 一次导入批次只属于一个产品；视频默认不勾选。
4. 每个待归类视频至少选择一个标签；同一标签分类下最多选择一个名称，不同分类可组合。
5. 确认后把服务端暂存的原视频移动到素材根目录下的产品目录，并重命名为 `产品-标签1-标签2.ext`；重名使用数字后缀。
6. 移动前校验产品、路径、格式、媒体信息、标签和冲突；批次部分失败时回滚已经移动的文件。
7. 保存原始路径、当前路径、时长、分辨率、产品和标签。

Windows 文件选择器允许一次选择多个视频；选择后通过既有上传接口进入服务端暂存区，再执行上述归类事务。客户端不得再使用“商品、人物、场景、口播、其他”的文件名猜测分类。

### 3.2 内容文库

文案：

- 输入参考文案后由百炼分析语言风格、受众和专家角色，并生成 5 条候选。
- 每条候选必须“采纳”或“不采纳”；不采纳必须填写原因。5 条全部审核后才能继续下一轮。
- 不输入参考文案时使用全局已采纳文案快照；文案库为空则阻止生成。
- 文案库与分析迭代记录物理分离，文案支持新增、编辑、删除和产品关联。
- 音频转文案支持抖音短链接、本地视频或本地音频；识别结果经人工确认后才进入文案库。

音色库：

- 展示 Qwen3-TTS Plus 的 597 个官方基础音色，序号固定为 1–597。
- 支持关键词、性别、年龄和场景筛选。
- 试听音频首次生成后缓存，后续复用。

旁白与字幕：

- 用户可手工输入或从文案库模糊选择文案，再选择音色序号生成 TTS。
- 根据真实音频时长生成字幕时间轴；用户可确认、修订或删除。

### 3.3 背景音乐

- 支持上传本地音频/视频，或从短视频分享链接提取音频。
- 入库前验证存在有效音频并拒绝近乎静音的文件。
- 单播放器试听；支持重命名、自定义多标签和删除。
- 被草稿引用的音乐禁止删除。
- 不做 BPM、波形编辑、节拍点、卡点或自动裁切分析。

### 3.4 剪映草稿

- 文案、旁白字幕、背景音乐均为可选，但三者至少选择一项。
- 不向草稿写入任何视频媒体或视频片段；用户在剪映中自行添加、裁切和排序视频。
- 检测并确认剪映草稿目录，检测失败时允许手动指定并持久化。
- 生成真实剪映草稿文件，包括 `draft_content.json`、`draft_info.json`、`draft_meta_info.json`、相关 sidecar 和说明。
- 旁白、音乐复制到草稿自己的 `assets/audio`，不引用易失的上传路径。
- 草稿时长取字幕结束、旁白和音乐时长的最大值；只有文案时至少 5 秒。
- 同一素材组合重复时提示累计次数但不阻止；可重置计数基线。
- 草稿名带时间戳；目录冲突时追加 `-2` 等后缀，永不覆盖已有目录。
- 删除应用内草稿记录不删除磁盘上的草稿文件夹。

### 3.5 模型配置

- 文案生成、语音识别、字幕配音三张独立配置卡。
- 每张卡独立保存 API 地址、API Key 和模型 ID，支持连接测试与读取模型列表。
- 只记录真实业务调用日志；连接测试和模型列表请求不进入业务日志。
- 所有日志和界面必须脱敏 API Key。

## 4. 明确不开发

- 手工粗剪、代理视频、应用内视频时间线
- 自动选片、镜头相似度、节拍或卡点生产
- 成片渲染、成片库、爆款跟踪
- 无人值守批量生产、自动发布
- 框架库或版式编排

这些能力不得以“下一步优化”为由重新进入 Windows 客户端。

## 5. 桌面端交付规则

- 发布为 Windows x64 自包含目录，目标机无需安装 .NET。
- 使用系统 Edge WebView2 Runtime 承载工作台；目标机已验证安装。
- 默认服务地址为 `http://192.168.31.24:8000/workbench/`，部署时可用 `JVA_WORKBENCH_URL` 覆盖。
- WebView2 使用 `%LocalAppData%\JianyingVideoAssistant\WebView2` 保存会话；不把密码写入客户端配置。
- 服务不可达、显示进程失败或 WebView2 缺失时必须显示原因、重试和浏览器替代入口。
- 外域新窗口交给系统浏览器，工作台内部导航留在应用内。

## 6. 验收标准

- 桌面程序打开后看到的导航、数据和功能与 `.24` 当前工作台一致。
- 登录一次后重启客户端仍能恢复 Web 会话。
- 产品与标签管理、素材上传归类、文案迭代、音色试听、旁白字幕、音乐、草稿和模型配置均复用现有后端，不产生第二套本地数据。
- 服务离线时应用自身不崩溃，并能在服务恢复后重试。
- 发布包整体复制到目标机即可启动，不要求安装 .NET。
